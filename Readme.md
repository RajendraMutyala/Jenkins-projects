# CI/CD Pipeline Automation Using Jenkins, Maven, and Docker

## Project Overview

This project demonstrates the implementation of an automated Continuous Integration and Continuous Deployment (CI/CD) pipeline using Jenkins, GitHub, Maven, and Docker.

The pipeline automates the process of retrieving Java application source code from GitHub, building and packaging the application using Maven, creating a Docker image, deploying the application in a Docker container, and verifying the application's HTTP response.

The primary goal of this project is to reduce manual deployment effort and demonstrate an automated software delivery workflow using DevOps tools.

## Technologies Used

- **Git & GitHub** – Source code management and version control
- **Jenkins** – CI/CD pipeline automation
- **Java 17** – Application development and runtime
- **Apache Maven** – Application compilation and packaging
- **Docker** – Application containerization and deployment
- **Linux / Shell Scripting** – Execution of pipeline commands
- **HTTP / cURL** – Application availability verification

## Architecture and Workflow

The pipeline follows this workflow:

```text
Developer
    |
    v
GitHub Repository
    |
    v
Jenkins SCM Polling
    |
    v
Git Checkout
    |
    v
Maven Build and Packaging
    |
    v
Executable JAR Artifact
    |
    v
Docker Image Creation
    |
    v
Docker Container Deployment
    |
    v
HTTP Response Verification
    |
    v
Application Running
```

### Pipeline Stages

**1. Git Clone**

Jenkins checks out the latest source code from the configured GitHub repository and the `main` branch. It verifies that the expected Java application source file exists before proceeding.

**2. Maven Build**

Jenkins executes the following command:

```bash
mvn -B clean package
```

Maven cleans previous build output, compiles the Java source code, and packages the application into an executable JAR file.

The pipeline verifies that the generated artifact exists and archives the JAR in Jenkins.

**3. Docker Image Creation**

Jenkins builds a Docker image using the project's Dockerfile and the JAR generated by Maven.

The image is tagged using the Jenkins build number and also receives a `latest` tag.

For example:

```text
jenkins-projects:15
jenkins-projects:latest
```

The actual numeric tag depends on the Jenkins build number.

**4. Deployment**

Jenkins removes the previous application container, if one exists, and starts a new container using the image created during the current build.

The container configuration includes:

- Container name: `jenkins-projects-app`
- Host port: `8081`
- Container port: `8080`
- Restart policy: `unless-stopped`

**5. Deployment Verification**

After starting the container, Jenkins checks its status and waits briefly for the application to start.

It then sends an HTTP request to the application endpoint using cURL. The request is retried up to five times if necessary.

If the HTTP request fails, the pipeline reports a failure.

## Project Files

| File | Purpose |
|---|---|
| `Jenkinsfile` | Defines the CI/CD pipeline, triggers, stages, deployment commands, and post-build actions |
| `pom.xml` | Defines the Maven project, Java version, build plugins, and application entry point |
| `Dockerfile` | Defines the Java runtime image and instructions to run the packaged application |
| `src/main/java/com/example/App.java` | Contains the Java application source code |
| `target/` | Contains the JAR generated by Maven during the build |

The `target/` directory is generated during the Maven build and does not need to be maintained manually.

## Jenkins Pipeline Configuration

The pipeline is defined in the `Jenkinsfile` using Jenkins Declarative Pipeline syntax.

### Source Code Repository

```text
https://github.com/RajendraMutyala/Jenkins-projects.git
```

### Branch

```text
main
```

### Automated Trigger

```groovy
triggers {
    pollSCM('H/2 * * * *')
}
```

This configuration instructs Jenkins to poll the source repository approximately every two minutes and trigger a build when it detects changes.

### Environment Configuration

| Variable | Value | Purpose |
|---|---|---|
| `GIT_URL` | GitHub repository URL | Source repository |
| `GIT_BRANCH` | `main` | Branch to build |
| `DOCKER_IMAGE` | `jenkins-projects` | Docker image name |
| `CONTAINER_NAME` | `jenkins-projects-app` | Deployment container name |
| `APP_PORT` | `8081` | Host port for application access |

## Maven Configuration

The Maven project uses the following configuration:

- Group ID: `com.example`
- Artifact ID: `jenkins-projects`
- Version: `1.0.0`
- Java release: `17`
- Main class: `com.example.App`

The generated JAR file is:

```text
target/jenkins-projects-1.0.0.jar
```

The Dockerfile copies this JAR into the container and launches it using the Java runtime.

## Docker Configuration

The Dockerfile uses the Eclipse Temurin Java 17 JRE image as its base image.

```dockerfile
FROM eclipse-temurin:17-jre

WORKDIR /app

COPY target/jenkins-projects-1.0.0.jar app.jar

CMD ["java", "-jar", "app.jar"]
```

This approach separates application building from container image creation. Maven compiles and packages the application, while Docker provides a consistent runtime environment for deployment.

## Prerequisites

Before running the pipeline, ensure the Jenkins execution environment has:

- Jenkins with Pipeline and Git support
- Git installed and access to the GitHub repository
- Java 17 and Maven installed
- Docker installed and running
- Permission for the Jenkins execution user to run Docker commands
- cURL installed
- Network access required to retrieve dependencies and base images

The Java application must listen on container port `8080` for the configured port mapping and HTTP verification to work.

## Running the Application Locally

### 1. Build the JAR

From the project root, run:

```bash
mvn clean package
```

### 2. Build the Docker image

```bash
docker build -t jenkins-projects:local .
```

### 3. Run the container

```bash
docker run -d \
  --name jenkins-projects-app \
  -p 8081:8080 \
  jenkins-projects:local
```

### 4. Verify the application

```bash
curl -i http://localhost:8081/
```

The application should return a successful HTTP response if it starts correctly and supports the requested endpoint.

To view the running container:

```bash
docker ps
```

To view application logs:

```bash
docker logs jenkins-projects-app
```

## Accessing the Deployed Application

After a successful deployment, access the application using:

```text
http://YOUR_SERVER_PUBLIC_IP:8081
```

Replace `YOUR_SERVER_PUBLIC_IP` with the public IP address of the server hosting the Docker container.

Ensure that the server's firewall or cloud security group permits inbound traffic on port `8081` if external access is required.

## Error Handling and Build Artifacts

The pipeline includes several validation and error-handling measures:

- Verifies that the Java source file and `pom.xml` exist.
- Checks that the Maven-generated JAR is not empty.
- Verifies Docker availability and the presence of the Dockerfile.
- Stops shell execution when a command fails or an undefined variable is used.
- Archives generated JAR files in Jenkins and enables artifact fingerprinting.
- Checks container status and retries the HTTP verification request.
- Reports pipeline success or failure through Jenkins post-build actions.

These checks help identify build and deployment failures through the Jenkins Console Output.

## Current Implementation Scope

This implementation provides automated source retrieval, Java application packaging, Docker image creation, container deployment, and HTTP-based deployment verification.

The current pipeline does not include a separate unit-testing stage, pushing images to a remote container registry, or deployment to a container orchestration platform such as Kubernetes.
